# 上下文读取器验证设计

本文件记录 P00 设计；未列为“已通过”的测试均尚未执行。用户本轮的交付目标是完成接入与 8289 实测，阻塞题未全过时记录 P0；不以全过为本轮完成条件。

## 同输入材料对照

冻结活动 revision、查询规划、召回、RRF、重排输出、模型配置与生成预算，只切换 `legacy` / `shadow` / `candidate` reader。`shadow` 复用同一份 ranked seeds，旧路径负责输出；新 reader 仅产生 L2/L3 对照，不新增 Embedding、Reranker、LLM 调用。验收分别记录：来源节点覆盖、候选包覆盖、实际 HTTP body 中阅读单元覆盖、最终答案完整性。

## 必测合成场景

1. 单 seed 回读同一真实节点的 1、2、9 段及有重叠的片段；缺中段与未知源终点必须标不完整。
2. 纵向合并跨两行：目标行继承共享列，保留本行其它列，绝不继承上一行其它数值；段落锚点行号为空但结构路径、atom 映射与 IR 一致时仍可核验。
3. 表头与目标表的 part/story/table 身份不一致、跨文档版本、源 node 缺失、同坐标文本冲突，均不能组成完整事实。
4. 列表条目跨 Chunk、同文本位于不同来源、同节点重叠去重、反序输入与稳定排序。
5. 读取 I/O 限额、Token 组预算、取消及终端预算不足，均显式记录原因；不能把不完整材料伪装成“无答案”。
6. 三模式服务指纹与答案缓存隔离；默认 `legacy` 等价；`shadow` 不新增模型请求；公共 SSE 状态与引用合同保持合法。
