# 阶段决策门

## 必须暂停

- 需要真实账号、API Key、付费、实名认证或文档内容出公网；
- 需要删除/重建用户索引、破坏数据或执行不可逆迁移；
- 需要改变已发布公共 API、配置键、数据模型或兼容边界；
- 需要改变已经 Accepted 的 ADR 或跨阶段工程合同；
- DOCX 修订、批注、页眉页脚等正文语义存在两种业务上明显不同的解释；
- 发现依赖许可证、商用条款或数据合规风险；
- 基线出现与当前阶段无关且未获授权修复的源码失败；
- 远程同名分支存在未知提交或并行开发冲突；
- 没有真实评测数据却要求宣称效果提升或生产可用。
- 高级算法未达到晋级门槛却准备默认启用；
- 准备大规模删除 legacy/Industry 代码；
- 准备发布 PyPI、确定公共包名或许可证；
- 准备把 `feature/universal-rag` 合入原始 `main`。

普通实现选择、可逆测试修复和任务书已授权的最小代码调整不进入决策门。

## 决策文件模板

决策文件写入 `docs/decisions/DECISION_REQUIRED_phase_NN.md`，至少包含：

1. 事实证据：命令、返回码、SHA、失败位置；密钥和正文必须脱敏。
2. 可选方案：每项写明代码、数据、兼容性、成本和恢复影响。
3. 推荐项：说明为什么在当前边界下风险最低。
4. 需要用户回答的一句话：只询问会改变路线的必要选择。

## 恢复规则

用户给出明确选择后，先重新核对分支、远程和工作区，再只执行获授权方案。新的独立
决策门仍需再次记录；不得把一次授权解释为真实数据出站、破坏性操作或公共 API 变更
的长期授权。
