# 湾事通阶段计划

## 规划原则

- 每个阶段从最新 `origin/feature/wanshitong` 创建独立 `codex/wb-*` 分支。
- `feature/universal-rag` 与 `Industry` 在湾事通开发期间保持只读参考。
- 阶段分支通过独立 Verification Prompt 后才能合入 `feature/wanshitong`；WB-00 不执行
  集成合并。
- 下列后续阶段是依赖顺序与验收范围，不是 WB-00 的实现授权。具体变更仍须由各阶段
  Prompt 明确批准。

## WB-00：基线与合同

目标：建立独立开发基线，不改变现有 RAG 行为。

- 创建并推送 `feature/wanshitong`；
- 创建 `codex/wb-00-bootstrap`；
- 固化入口、会话、知识库、History、模型容量、OCR 和轻量门禁合同；
- 只运行文档与 Git 轻量验证。

完成标志：阶段分支只包含指定文档，已推送但未合入集成分支。

## WB-01：服务端范围与容量

候选目标：在不改变通用默认行为的前提下，增加湾事通专用组合配置。

- 服务端固定 Project/KB，并对文档元数据过滤失败关闭；
- 长期 Token 只在服务端解析，公共浏览器只接收同源会话；
- 接入既定 Industry 模型 Endpoint 与每类最高 4 并发；
- 定向验证 `4 active + 8 queue` 的接纳与超限语义。

## WB-02：公共会话与 History

候选目标：完成无登录公共会话和 7 天加密 History 的 API/持久化合同。

- 会话只能访问服务端固定的数据范围；
- 问题、答案及必要会话内容加密落盘，密钥不进入浏览器；
- 实现并验证 7 天到期清理；
- 保持管理员能力与公共会话边界分离。

## WB-03：双入口界面

候选目标：实现公共 `/` 与管理员 `/admin`，不引入第一版之外的交互。

- 公共页面隐藏 Project/KB 选择；
- 第一版不展示快捷入口；
- 管理页面只操作一个知识库及其文档元数据；
- PaddleOCR-VL 未配置时，前端明确禁用 PDF 上传并说明原因。

## WB-04：内网部署与 Demo 验收

候选目标：按独立部署授权将湾事通暴露在内网 HTTP `8188`，完成必要 build 与 smoke。

- 核对模型 Endpoint、凭据注入和 OCR 配置状态；
- 对入口、元数据过滤、History、并发/队列、禁用 PDF 路径做定向验收；
- 不以轻量 Demo 结果声称公网安全、生产可用或模型质量达标。

后续阶段可由验证结果拆分，但不得把未完成项回填成 WB-00 已实现能力。
