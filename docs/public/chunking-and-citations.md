# 分块与引用说明

系统把 Word 文档先解析为格式中立的 Document IR。DOCX 按标题、段落、列表、表格、
脚注、图片说明和文本框等结构生成 Chunk，不会先把原文拼成一大段再猜位置，因此每个
可见字符都能追溯到 OOXML 节点或明确的自动编号。

旧版 DOC 先由受限本地转换器降级为正文纯文本段落，再进入同一 Chunk 管线；其跨度只能
追溯到降级后的段落节点，不代表二进制 DOC 中的表格、图片、页眉页脚、批注或修订结构
已经保留。解析报告会记录 `LEGACY_DOC_FLATTENED_TEXT`。

## 三种文本为什么不同

- `citation_text` 是用户可核对的证据正文，保留原字符，并记录精确来源跨度。
- `embedding_text` 在证据外增加确定性的文档名、标题路径、内容类型或表头，帮助后续
  Embedding 理解位置。这些上下文不是额外证据。
- `lexical_text` 为关键词和编号检索做 Unicode、大小写和标点规范化，同时保留产品号、
  标准号与版本号等 identifier。

界面引用和最终答案只能使用 `citation_text`。不得从 embedding-only 上下文或规范化后的
lexical text 直接摘引原文。

## 引用跨度

来源跨度分为原文、自动编号、重复上下文和分隔符。原文和重复上下文都指向真实 Document
IR 节点及字符范围；自动编号指向对应列表段落和编号定义；换行等分隔符不可引用。

重复上下文包括长文本切分时复制的完整上一句、表格后续块复制的真实表头，以及纵向合并
单元格显示的锚点值。它们仍可追溯到首次出现的位置，并带有重复标记，不能伪装成当前位置
的新原文。

一个 quote 只有在以下条件满足时才能发布：

1. 完整位于可引用 span；或多个连续 span 能无歧义地映射到同一来源；
2. 不跨不可引用 separator 或不同来源跳转；
3. 不包含只为 Embedding 添加的标题、位置、类型或表头前缀。

## 结构行为

- 普通段落和连续列表项按原顺序装包，不跨标题 section 或 run。
- 列表显示自动编号，编号重启和不同 numId 不会被错误视为同一列表。
- 表格按完整行处理；合并单元格与嵌套表格保留结构关系，嵌套表格用 child group 关联。
- 脚注和尾注默认是独立 note，正文保存引用关系，不把 note 偷塞进正文证据。
- 有语义的图片 alt/caption 可检索；图片字节和 OCR 结果不会在本阶段成为正文证据。
- 页眉、页脚和批注默认只保留 metadata；明确 profile 才会生成独立 chunk。

## 限制与声明

当前 `384/512/64` 参数仍是 provisional。离线结构消融只能发现超限、边界、覆盖或稳定 ID
问题，不能证明哪个参数检索效果最好。真实 Embedding、Reranker、企业文档、OCR 与生产
Qdrant 均需在后续受控阶段单独验证。
