## 系统性修复方向

按“召回是否覆盖所问资料 → 证据是否足够回答所问关系 → 生成事实是否有
引用 → 回答是否覆盖问题全部条目”四层区分失败。相邻段落中的列表导语
本身不是条目，不能因为逐字引用了导语就宣称回答了“哪些情形”。

1. 继续使用现有 FTS/Exact、Dense、融合和 Reranker；先按题型、来源与
   否定/数量约束评估召回质量，再决定是否扩展同节相邻片段，不以增加
   Top-K 或塞入整份长文替代定位。
2. 共享的 `QuerySemantics`、`AnswerSupport` 和 `EvidenceAssembler` 消费
   同一个问题契约。编号列表需要闭合成完整、可回溯的来源组；不能把
   导语、下一节或相似文档拼成事实。
3. `GroundedAnsweringService` 先核验每条 claim 的原文、对象、数字和否定，
   再在完整草稿上核验结构化列表覆盖；不完整时一次有界修复，仍不成立
   就明确拒答。增量 claim 不能先于最终完整性门发布。
4. 每份文档至少有直接问法、改写问法与对抗问题；一次跑完整题库后按
   Trace 区分召回缺失、证据不足、生成校验和答案不完整，再统一修改
   共享机制并重跑同一题库。模板只允许提示存在与参考名称。
5. 书名号中的完整标题作为精确召回信号，但“命中标题”不直接等于
   “知道模板正文”。只有标题、来源显示名和受信任目录项三者一致时才
   支持存在/参考；字段、示例、填写要求仍按无正文证据处理。

方向参考：[CRAG 的检索质量评估与纠错](https://arxiv.org/abs/2401.15884)、
[Anthropic 的上下文检索/混合召回实验](https://www.anthropic.com/engineering/contextual-retrieval)、
[RAGBench 的可解释评估框架](https://arxiv.org/abs/2407.11005)、
[长上下文中间信息容易遗漏的研究](https://aclanthology.org/2024.tacl-1.9/)、
[多跳问题分解研究](https://arxiv.org/abs/2507.00355)。
这些是算法设计参考，不把论文数据直接当成湾事通的质量指标，也不引入
第二套知识库或离线服务器无法获取的在线依赖。
[GraphRAG 的研究](https://www.microsoft.com/en-us/research/publication/from-local-to-global-a-graph-rag-approach-to-query-focused-summarization/)
针对跨全语料的宏观主题总结；本轮主要是流程/制度的局部事实和结构闭合，
因此不为这个 Demo 新建图索引。这里是根据任务形态作出的工程取舍，
不是声称图检索普遍无效。
