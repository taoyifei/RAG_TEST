## 已实现的修复

- 配置诊断通过只读 SQL 核对连接、凭据元数据、Profile 与 campaign；不构造 Product Runtime、解密 Credential、执行产品 migration 或发出 HTTP。异常分成稳定字段码和有界中文操作说明，未知 SQL/代码异常保持失败。
- 可信北京 API Host 接受裸主机、HTTPS Origin 与等价 `:443/`，保存前显示规范结果。userinfo、IP、私网、其他地域、相似后缀、路径/query/fragment、转义分隔符和 Unicode 混淆继续拒绝。Workspace 只做 opaque ASCII 形状验证，不猜值、不改前缀。
- `endpoint_contract`、`connection_configuration`、`campaign_binding` 独立聚合；Jina 的有效单步证据不会因百炼配置或 UTC 跨天而失效。复用还必须满足实际 24 小时 TTL、配置/凭据/策略/维度、已批准 payload 和持久授权，不能只检查 PASS 与哈希。
- 初始 campaign 不可变；追加修订与预留共享 SQLite 写事务，使用累计总限额，保留成功、失败、未知转发与无 usage 历史。修订重放幂等，错链/错 scope/错批准集、缺批准人、过期、低于已用、缺子限额均拒绝。
- 历史 validation 与 operation event 在同一个只读事务核对，只有唯一匹配才合并，无法确认的转发保守占用。首绑重放不重复导入 Transport 已记账的事件。恢复带账本或首绑前无账本的旧备份都留下 restore-blocked，不能重新领取旧额度。
- 恢复后的双槽离线测试只允许精确匹配的内建固定内存响应器继续，不改账本、不移除恢复标记；普通 Mock、自定义工厂和真实 HTTP 仍被阻断。该类型不接受可出网 handler，维护互斥仍有效。
- 完整 Trivy 原始扫描不可修改。有效 overlay 精确匹配镜像、CVE、包、版本、扫描/DB 与证据哈希；客观不受影响结论必须有发行版结构化证据，风险接受必须有真实人工批准和期限。最终聚合重新校验到期与证据，不新增状态枚举。CI 同时归档未过滤扫描，`ignore-unfixed` 子门明确仅阻断可修复 High/Critical。
- 维护首绑只停原本运行的目标 App，`finally` 恢复同一容器；原本停止的实例不启动，不动 Qdrant。普通 canary 不进维护，首绑不嵌套全量验收。`--exit-scope selected` 只改变所选动作退出码，整体发布状态仍独立。
