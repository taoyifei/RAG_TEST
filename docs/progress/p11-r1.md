## 修复内容

1. 外部 Token 使用方法和完整路由模板白名单，未知控制面默认拒绝。
   管理员 Session 保留 CSRF；只有显式传入 legacy 配置才允许旧 Bearer。
   Provider 凭据、连接写入/测试、访问 Token 管理、检索方案管理均为管理员专用。
   外部授权完成后才桥接 P09，并保存独立 external_token 主体标记。
2. query:read 仅限所属 Project/KB 的 search/answer；原文和 Artifact 不属于该 Scope。
   knowledge:read 支持受限文档、版本、任务和索引只读，任务列表必须指定完整范围。
   Job ID 从持久记录解析归属；Artifact 先验证项目/知识库/文档版本引用链，之后才
   授权 Token。Profile 管理路由对全部外部 Token 拒绝，包括仅含 revision ID 的路由。
   knowledge:write 允许受限文档写入和作业重试/取消，不允许 Token 签发或付费 Probe。
   system:read 只读 system/components，不读取全局凭据。
3. AliyunEndpointConfig/Resolver 分离不透明 ID 形状与 DNS label 校验；仅北京
   HTTPS Origin，拒绝注入、IP、其他端口、路径、伪造后缀和重定向，关闭环境代理继承。
   API Host 不根据 ID 前缀推导；北京 DashScope 必须显式选择。Native 协议、模型、
   向量语义和固定路径不变，不自动重建向量。
4. PATCH 支持非 Secret 字段、预算和启用状态，必须 expected_version；并发冲突 409。
   不接受 secret_value/credential_id 等额外字段，保留连接 ID、Credential ID、
   密文、nonce、Key 字节与 key_version。配置保存和验证失效在同一事务中完成。
   Client 缓存包含连接 ID、配置版本、凭据版本和规范化端点。
5. 组合创建先验证完整元数据再创建 Credential；失败只补偿本次新建孤立凭据，
   已共享凭据不能被补偿删除。前端可选择已有适配凭据，编辑连接无需重新填 Key。
6. 追加 0016 migration，不改已应用 SQL；数据库合同范围升级为 16。旧验证记录保留，
   新验证记录增加配置版本和安全诊断。配置变更后旧 Probe 不能覆盖新连接状态。
7. Probe 和 Adapter 共用请求与响应编解码。保留业务状态、数量、唯一 text_index、
   维度、有限数值和 usage 合同；HTTP 200 不等于向量合同通过。
8. 诊断包含 stage、request_dispatched、HTTP 状态、白名单 Provider code、有界请求 ID、
   安全 host、operation/model 和配置版本。原始 message/body、输入文本、Secret 不记录。
   本地配置拒绝不进入 Provider 调用计数，历史 HTTP 4xx 仍保持失败。

## 运行边界与剩余风险

- `ALIYUN_LIVE_READY=false`。未实测北京 DashScope 对目标 Key/模型/业务空间的授权。
- 不添加猜测的子空间 Header；控制台 API Host 和一次真实脱敏响应仍待后续授权。
- Probe 用锁等待在途请求结束再关闭旧 Client；Profile 旧服务退役后保留到 Runtime
  shutdown 再关闭，避免中断在途查询/作业。频繁编辑会暂时增加进程资源占用。
- 未运行 Live、release build/verify/完整 acceptance、镜像构建、备份/恢复、重新部署、
  付费模型或真实 Qdrant 门禁；这些由后续适用阶段执行。
- 未运行 R4 全部适用发布门，禁止将 R1 本地就绪解释为 P11/产品发布就绪。
