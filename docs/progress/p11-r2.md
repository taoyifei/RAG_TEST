## 已实现合同

### 参数只解析一次

`ResolvedEmbeddingSpec` 持久化 provider、model、dimension、normalization、
adapter revision、connection 引用、Catalog 版本及 document/query policy。
同一对象驱动 Adapter HTTP 参数、SlotIdentity、指纹、验证身份和 UI 回读。
Product Resolver 不再用备用 Adapter 默认值覆盖用户策略。

Qwen 规范字段为 `query_instruct`，准确写入 query 请求的
`parameters.instruct`；document 请求不携带 query instruct。
Jina 保持 `retrieval.passage` / `retrieval.query`，页面不提供其 instruction。
未知键和不支持的任务、归一化值返回 422。
规范输入为布尔 `normalized=true`；当前适配器不支持关闭归一化，明确拒绝 false。
历史 `instruction` / `normalize` / `normalization` 输入要求显式迁移，
不静默转换；旧记录不能冒用新策略验证，但本地管理页仍可读取未验证状态。

Evidence 的规范来源是完整 `RetrievalPolicy`。兼容输入
`evidence_policy.minimum_units` 映射 `minimum_support_items`；重复冲突和
未知字段拒绝。最少支持数适用于所有可回答查询，最大证据数和 Token 上限
驱动实际 EvidenceAssembler。普通表单不能自称已完成 dense 校准。

### 身份、影响与缓存

Index identity 包含运行时真实 parser/parsing、chunker/chunking、FTS、
payload 合同及两个独立向量空间；本轮保留 query policy 纳入 Index 的保守规则。
Serving identity 包含检索、Evidence、Confidence、Reranker、failover 和预算。
UI/API 回读额外提供 `effective_serving_fingerprint`，与运行服务共用
`serving_contract`，体现当前连接预算、出网约束和已接受校准证据。

| 修改 | 索引影响 | 运行时处理 |
| --- | --- | --- |
| 同一 resolved 语义、显示名、Workspace 元数据、Credential 轮换 | NO_REINDEX | 连接版本变化使验证和相关服务缓存失效 |
| Evidence、failover、预算、允许的降级策略 | SERVING_RELOAD | 重建兼容服务和结果缓存 |
| 模型、维度、document/query policy、解析/分块/词法语义 | NEW_INDEX_REVISION_REQUIRED | 候选持久作业完成后原子发布 |

影响预览和应用共用现有 `preview_profile`。Credential 字节不进入数学身份。
缓存包含精确 Profile Revision 和连接/configuration/credential/endpoint 状态；
同语义的新 Profile 不会误拿旧 Profile 的快照约束。权限验证仍在缓存命中前执行。
退役服务保留至 Runtime 关闭，关闭顺序先停止作业再关闭 Provider 资源，
避免编辑或轮换时关闭在途查询持有的 Client。频繁编辑的资源占用会暂时增长。

### Profile 和索引共同发布

有文档时，语义变更创建既有 DurableJobRunner 作业，冻结候选 Profile、
文档版本快照、验证 ID 和预期的两个 Active 指针。入队和最终激活都核验
验证记录的连接/凭据版本、启用状态和 24 小时有效期。
构建期间旧方案和旧索引继续服务；双槽向量、FTS、SourceSpan、Inventory
通过既有 Validator 后，同一 SQLite 写事务/CAS 切换两个指针。
失败、取消、竞争发布或过期 Writer 不改变旧指针。

构建复用已有向量缓存，只补缺失向量。已达到 READY、激活前进程中断的
持久作业可重新取得 Lease、复验并完成发布，不重做已完成向量构建。
查询读取包含 Profile Revision、Index Revision 和过滤权限的不可变快照；
旧服务在切换后新开请求若不兼容则在 Provider 调用前 fail closed。
已取得旧快照的请求可完成，Hydration 不改读新 Active 指针。
空知识库允许绑定方案，但没有伪造 ActiveRevision，`index_ready=false`。

### 验证、质量和就绪状态

Provider 验证按该方案实际使用的 connection、configuration version、
credential key version、规范端点、operation、model、dimension、resolved
request policy、mock/live mode 和时间匹配。无关连接不能满足准入。
连接全部可用状态聚合每个 required operation，单个成功操作不能替代全部成功。
没有 Active Profile 时不借用全局连接最近成功结果。

新增持久、不可变的 `QualityValidationRecord`，区分 local contract、offline
evaluation、connectivity、dual-slot function、retrieval quality、release candidate。
受信任 Python 验收入口可导入带 run ID、dataset/report SHA 和完整绑定的记录；
普通 Profile API 没有提交质量认证的入口。记录不存在或绑定失效则为未验证。

独立检索质量固定门槛为 live、独立 holdout、至少 20 个标注 Query、10 个负例、
citation source precision >= 0.90、recall >= 0.80、negative leakage = 0，
且指定 gates 全部通过。接受记录只校准当前方案的实际 vector spaces 和 Reranker。
Connectivity 不晋级 Quality，Mock 不晋级 Live；test-only transport 即便注入
合成的全套“live”记录，也不启用真实 dense calibration 或 production ready。
测试中另用受控状态替身证明全部前置满足时计算可以为 true，不把这项测试当作 Live 证据。

`offline_evaluation_ready` 只来自匹配的离线 run/gates 记录，FTS schema 名称
不能产生该状态。本轮评估结果是独立离线产物，没有向用户运行库导入认证记录。
